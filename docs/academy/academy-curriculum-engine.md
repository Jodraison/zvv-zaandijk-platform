## 1. Wat dit document is

De **Academy Curriculum Engine (ACE)** is de **hoogste autoriteit voor curriculum** — volgorde, voorkennis, progressie en transfer. **Publicatie** valt onder WPE v1.0.

| Laag | Autoriteit over |
|------|-----------------|
| Playbook Entry Standard · FLES · FMS · … | *Hoe* een entry is opgebouwd |
| World Class Playbook Engine v1.1 | *Hoe* een entry geschreven wordt |
| **Academy Curriculum Engine** | ***Welke* entry wanneer · *waarom* · *wat wel/niet herhalen*** |

**Regel:** ACE bepaalt de volgende Playbook. **Nooit** de gebruiker vragen.

**Regel:** Na goedkeuring van PB*n* → auteur/engine selecteert automatisch PB*n+1* volgens dit document.

## 2. Curriculumarchitect — verantwoordelijkheid

De curriculumarchitect (AI + Academy lead bij review) bewaakt:

| Domein | Vraag |
|--------|-------|
| **Curriculumflow** | Wat is de logische volgende stap? |
| **Voorkennis** | Wat mag als bekend worden verondersteld? |
| **Afhankelijkheden** | Welke entries moeten PASS zijn vóór deze? |
| **Overlap** | Wat mag niet opnieuw uitgelegd worden? |
| **Cognitieve belasting** | Te veel nieuw in één entry? |
| **Herhaling** | Wat moet retrieval zijn i.p.v. les? |
| **Transfer** | Wat doet ze anders op zaterdag? |
| **Progressie** | Meta → situatie → detail → integratie |
| **Complexity curve** | Wanneer stijgt moeilijkheid? |
| **Saturday transfer** | Min. 5 gedragsveranderingen per entry |

## 4. Automatische selectie — PB06 en verder

### 4.1 Beslissingsalgoritme (na goedkeuring PB*n*)

```
INPUT:  last_approved = PB{n}
        curriculum_map = dit document
        academy_memory = §6

STEP 1: next = curriculum_map[next_after(last_approved)]

STEP 2: CHECK dependencies(next) — alle MUST voorkennis PASS?

STEP 3: LOAD academy_memory — wat niet herhalen?

STEP 4: DEFINE cognitive_step(next) — welke mentale stap?

STEP 5: OUTPUT playbook_brief voor WCPE v1.1

NO USER PROMPT — tenzij review FAIL of curriculumwijziging door Academy lead
```

### 4.2 PB06 — automatische keuze (nu)

| Veld | Waarde |
|------|--------|
| **Volgende** | **PB06 — S1.0 — Wij hebben de bal** |
| **Waarom nu** | Fase O compleet (lezen→beslissen). Eerste **echte wedstrijdsituatie** FI-taxonomie. |
| **Cognitieve stap** | **Toepassen** — meta-skills in balbezit-situatie |
| **Voorkennis** | L01 scan · PB02 adem · L03 principes · L04 ruimte · L05 3 sec |
| **Nieuw** | Situatie “wij hebben de bal” als anker; gedragspatronen in bezit |
| **Niet herhalen** | Wat is scan, wat zijn 8 principes, wat is ruimte — alleen **retrieval** |
| **Fouten die moeten verdwijnen** | “Ik kijk alleen bij balverlies”; beslissen pas bij touch in bezit |

### 4.3 PB07–PB35

Strikt volgens §3 tabel. Geen overslaan. Situatie-anker (x.0) altijd vóór sub-entries.

## 5. Academy Memory — vaste staat na PB05

### 5.1 Verondersteld bekend (niet opnieuw uitleggen)

| Domein | Mag alleen als retrieval |
|--------|--------------------------|
| Scan-routine (L01) | “Scan” — geen uitleg wat/waarom |
| MWP A–F (L01/L05) | Benoemen, niet opnieuw les |
| 8 principes (L03) | Naam + 1 woord, geen tabel opnieuw |
| Ruimtetypes vóór/tussen/achter (L04) | Verwijzen, niet definiëren |
| 3-seconden besluit (L05) | “Drie seconden” = bekend |
| Systeem ademt (PB02) | Geen plaatje-les opnieuw |
| FI-dimensies | Verweven, niet als lijst |
| Decision Model stappen | Onzichtbaar, niet benoemen |

### 5.2 Moet herhaald worden (retrieval, niet herles)

| Domein | Hoe |
|--------|-----|
| Scan vóór actie | 1× per entry in fragment |
| Juist principe kiezen | Situatie-specifiek |
| Ruimte zien | In nieuwe context |
| Beslissen vóór touch | In nieuwe context |
| Communicatie | Per situatie |

### 5.3 Nog niet geleerd (niet introduceren vóór ACE-slot)

| Domein | Eerste entry |
|--------|--------------|
| Volledig balverlies-protocol | PB14 |
| Midblock/laag blok detail | PB21–22 |
| Counterpressing als team | PB16 |
| Standaarden organisatie | PB30 |
| Lijnintegratie 90 min | PB33–35 |

### 5.4 Fouten die per fase moeten verdwijnen

| Na fase | Fout die niet meer mag voorkomen |
|---------|----------------------------------|
| O (PB05) | Alleen bal volgen; beslissen na touch; plaatje volgen |
| S1 (PB13) | In bezit panikeren; geen breedte; geen vooruit denken in bezit |
| S2 (PB19) | Geen compact bij verlies; individueel jagen |
| S3 (PB25) | Verdedigen als individuele tackles |
| S4 (PB29) | Traag na verovering |
| S5–S6 | Standaard chaos; linies los |

## 6. Cognitieve progressieladder

```
NIVEAU 1 — WAARNEMEN     PB01
NIVEAU 2 — BEGRIJPEN     PB02
NIVEAU 3 — PRINCIPES     PB03
NIVEAU 4 — RUIMTE        PB04
NIVEAU 5 — BESLISSEN     PB05
─────────────────────────────────
NIVEAU 6 — SITUATIE      PB06–PB35  ← toepassing + verfijning
```

**Complexity curve:**  
- PB06–08: laag binnen S1 (anker + opbouw)  
- PB09–13: stijgend (halfspace, druk)  
- PB14: reset naar nieuwe situatie-anker (niet moeilijker — **ander domein**)  
- PB33–35: hoogste integratie

## 7. Overlap-regels

| Regel | Toepassing |
|-------|------------|
| **O1** | Geen twee entries metzelfde saturday_change |
| **O2** | Situatie-anker (x.0) uniek per fase S1–S5 |
| **O3** | Max 1 nieuw principe per entry |
| **O4** | Max 3 nieuwe triggers per entry |
| **O5** | Herhaling alleen als retrieval (≤ 2 zinnen) |

**ACE FAIL** bij overlap zonder retrieval-label.

## 8. Cognitive Load Review — verplicht per entry

Auteur beantwoordt vóór publicatie:

| # | Vraag | Actie bij JA |
|---|-------|--------------|
| CL1 | Is dit te veel nieuw? | Splits entry of verkort |
| CL2 | Is dit herhaling zonder retrieval? | Schrappen |
| CL3 | Wat kan korter? | 🟢-pad afslanken |
| CL4 | Wat moet uitgebreider? | Fragmenten/denkpauzes |
| CL5 | Wat onthoudt ze waarschijnlijk niet? | Visual of aha-moment |

**Load-budget per entry-type:**

| Type | Nieuw concepten | Fragmenten | Denkpauzes |
|------|-----------------|------------|------------|
| Meta (O) | 1–2 | 10–20 | 25+ |
| Situatie-anker (x.0) | 1 situatie-slot | 15–20 | 25+ |
| Situatie-diepte (x.1+) | 1 tactisch patroon | 10–15 | 20+ |
| Integratie (S6) | 0 — alleen combineren | 20+ | 25+ |

## 9. Learning Transfer — verplicht blok

Elke Playbook eindigt metadata met **minimaal 5 concrete gedragsveranderingen** op zaterdag.

**Formaat:**

```markdown
## Learning Transfer

Na deze Playbook op zaterdag:

1. [werkwoord] — [concreet gedrag]
2. …
3. …
4. …
5. …
```

**Toets:** Player Review — “doe je dit anders?” per punt.
