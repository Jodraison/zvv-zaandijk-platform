## 1. Wat dit document is

Het **World Class Visual Learning Protocol (WVLP)** is de **hoogste standaard voor visueel leren** — hoe elke Playbook Entry leert via Praatje/Plaatje/Daadje/Transfer. **Gedrags- en publicatiecertificering** valt onder WPE v1.0.

| Prioriteit | Document |
|------------|----------|
| **1** | **WPE v1.0** — Performance · gedrag · certificering |
| 2 | **ACE** — welke Playbook wanneer |
| 3 | **WVLP** — 4 lagen · visuals |
| 4 | **WCPE v2.2** — schrijven · coach-stem |
| 5 | FLES · FMS · Language · Blueprint |
| 6 | Playbook Entry Standard |

**Einddoel:** De speelster denkt niet *“ik heb iets gelezen”* maar *“ik heb deze wedstrijd al een keer gespeeld”*.

**Academy-gevoel:** Geen website · geen documentatie · geen cursus · geen trainersmap — **het beste digitale voetbalbrein** dat een speelster ooit gebruikt.

**Na elke Playbook:** *“Nu snap ik eindelijk waarom dit gebeurt.”*  
Niet alleen weten → begrijpen → zien → **zaterdag automatisch herkennen**.

## 2. De vier lagen — elke uitleg

**Regel:** Elke **uitleg-eenheid** (concept, fragment, ketting, fout) in een Playbook **moet** vier lagen doorlopen. Geen laag overslaan.

### LAAG 1 — PRAATJE

| Eis | Toets |
|-----|-------|
| Zo simpel mogelijk | 14-jarige parafraseert |
| Geen jargon zonder context | Language Guide |
| Topsportniveau | Trainer herkent ZVV-DNA |
| Waarom-keten | Gouden regel WCPE |

**Verboden:** encyclopedie · definitie zonder situatie · “in deze les leer je”.

---

### LAAG 2 — PLAATJE

**Direct na Praatje — verplichte vraag:**

> *“Kan een afbeelding dit beter uitleggen dan tekst?”*

| Antwoord | Actie |
|----------|-------|
| **JA** | Visual **verplicht** — specificeer type (§5) |
| **NEE** | Geen visual voor deze eenheid — motiveer in metadata |

**Vier vragen vóór elke visual** (alle vier sterk — anders **GEEN** visual):

1. Welk **leerprobleem** lost deze afbeelding op?  
2. Waarom lukt dit **niet** met tekst?  
3. Wat ziet de speelster **ná** de afbeelding wat zij **daarvoor** niet zag?  
4. Wat doet zij **zaterdag anders** dankzij deze afbeelding?

**Visuals zijn geen decoratie.** Geen visual “omdat het mooi is”.

---

### LAAG 3 — DAADJE

**Geen theorie.** Wat doet de speelster **zaterdag**?

| Veld | Verplicht |
|------|-----------|
| Waar kijkt ze? | Scan-richting |
| Waar loopt ze? | Beweging vóór bal |
| Hoe staat haar lichaam? | Open / gesloten · hoek |
| Wanneer beweegt ze? | Timing · niet te vroeg/laat |
| Waarom juist dan? | Oorzaak → gevolg |
| Wat gebeurt er daarna? | +2 sec voorspelling (WCPE v2.1) |

**Formaat:** Fragment · MWP-stap · “Toepassing zaterdag” — minimaal één Daadje-blok per uitleg-eenheid.

---

### LAAG 4 — TRANSFER

**Geen “onthoud dit”.** Interactieve denkvraag:

- Wat zou **jij** doen?  
- **Waarom?**  
- Wat als jij **niets** doet?  
- **Wie** krijgt hierdoor een probleem?  
- Hoe verandert de **rest** van het team?

**Formaat:** STOP · DENK · BESLIS · WAAROM? — **vóór** het antwoord in tekst (Socratisch).

**Koppeling:** Learning Transfer (ACE) + FMS sectie 12 (beheersingssignalen) waar van toepassing.

## 4. Visual-hierarchie — 7 toegestane types

Alleen types met **aantoonbare leerwaarde**.

### TYPE 1 — Top-down veldvisual

Complete situatie: bal · spelers · ruimtes · zones · lijnen · afstanden.  
**Lost op:** “Waar is iedereen?” — overzicht.

### TYPE 2 — Tactische overlay

Pijlen · looplijnen · kantelen · compact · breed · diep · halfspace · restverdediging.  
**Lost op:** “Wat beweegt?” — proces op statisch veld.

### TYPE 3 — Frame-sequence

```
Frame 1 — Wat zie je?
    ↓
Frame 2 — Wat verandert?
    ↓
Frame 3 — Waarom ontstaat dat?
    ↓
Frame 4 — Welke keuze maken wij?
    ↓
Frame 5 — Wat gebeurt daarna?
```

**Lost op:** tijd · voorspelling · film niet foto.

### TYPE 4 — Split screen

Goed **vs** fout — **waarom**, niet alleen eindbeeld.  
**Lost op:** contrast · verkeerde overtuiging.

### TYPE 5 — 22-perspectieven

Zelfde moment — keeper · CV · … · spits · tegenstander · coach.  
Iedereen ziet iets anders.  
**Lost op:** systeemdenken · niet alleen eigen rol.

### TYPE 6 — Beslisboom

Wat zie je → opties → waarom → keuze → gevolg.  
**Lost op:** besluiten onder druk · geen één goed antwoord.

### TYPE 7 — Ruimte-evolutie

Hoe ontstaat · verdwijnt · wie veroorzaakt · wie sluit.  
**Lost op:** ruimte is dynamisch (PB04+).

| # | Element | Visual-type |
|---|---------|-------------|
| ✓ | Veldvisual | TYPE 1 |

| ✓ | Frame-sequence | TYPE 3 |
| ✓ | Split screen | TYPE 4 |
| ✓ | Beslisboom | TYPE 6 |
| ✓ | Ruimte-evolutie | TYPE 7 |
| ✓ | Wedstrijdfragment (tekst + beeld) | TYPE 1/3 + Daadje |
| ✓ | Interactieve vraag (Transfer) | LAAG 4 — min. 25× |

**Aanbevolen (niet vervangbaar door minimum):** TYPE 5 — 22-perspectieven bij systeem-entries (PB07+).

## 6. Zelfdwang na iedere sectie

Auteur beantwoordt **JA** op alle — anders sectie herschrijven:

| # | Vraag |
|---|-------|
| S1 | Kan ze dit zaterdag **letterlijk voor zich zien**? |
| S2 | Kan ze dit **natekenen**? |
| S3 | Kan ze dit **uitleggen** aan een teamgenoot? |
| S4 | Kan ze dit **herkennen** op zaterdag? |
| S5 | Kan ze hierdoor een **betere beslissing** nemen? |
| S6 | Kan een afbeelding dit **nóg beter**? → Zo ja: visual ontbreekt |

---

## 7. Golden Rule — uitleg is pas af wanneer

De speelster:

1. **Het ziet** (Plaatje + inbeelden)  
2. **Het begrijpt** (Praatje + waarom)  
3. **Het kan uitleggen** (Transfer + teamgenoot-test)  
4. **Het herkent** (zaterdag-trigger)  
5. **Het automatisch toepast** (Daadje + Learning Transfer)

**Eén niveau FAIL → itereren tot PASS.**
